# 四程名义GDS生成与检查说明

## 当前结论

**2026-09-05 更正：旧版仅检查三条回路彼此相交，漏掉输入/输出。完整路由中心线检查发现输入与回路2在约(623.281, 30.150) µm处以29.53°斜交。旧GDS不是光学功能通过版，历史文件保留。生成器现在默认拒绝输出这种未经设计的交叉；下面的旧版生成命令在修复真正写入GDS前会触发该保护。**

新候选在(300, 250) µm预留一个45×45 µm正交LN交叉器，输入走横向，回路2走纵向。输入、输出和三条回路的中心线检查没有额外非预期交叉，三条回路中心线长度保持不变。此候选**只完成中心线拓扑筛查，尚未替换到实际GDS，也未完成交叉器光学验证**。中心线等长不代表群时延相同：还需回填交叉器、宽度过渡和晶向相关群时延。

复现本次检查：

```powershell
.\.venv\Scripts\python.exe models\layout\check_crossing_candidate.py
.\.venv\Scripts\python.exe -m unittest discover -s models/layout -p test_route_geometry.py
```

输出位于`results/layout/正交交叉候选_v1/`：`光路拓扑检查.json`和`正交交叉_局部中心线.svg`。复现依赖本地历史检查JSON，默认路径在脚本中；这些本地结果不提交Git。后续GDS修改仍需检查包络、金属、黑盒边界和真实连接，不能以中心线筛查替代DRC。

当前名义版图已经把四次有源调制统一为从左向右传播，三条无源回路负责从右端返回左端，再进入下一阶模式。它修正了早期示意图中第二程、第四程反向穿过行波电极的问题。

在15 mm有源电极和10 GHz目标频率下，早期的2T、2.5T、2T时延只适合做理想相位关系对照，不能直接作为当前几何的实际回路长度：最短回路的总群时延长度不足以同时容纳15 mm有源段、两个模式复用器、渐变段和真实弯曲。当前可布名义值改为3T、3.5T、3T，仍保持“整数、半整数、整数”的相位条件。

这次调整不要求重新计算已经确认的1.33 µm直有源波导模式、直T形电极的10 GHz射频有效折射率和直段电光重叠。需要重新闭合的是实际回路群时延、四个模式复用器完整级联以及新版时延下的系统频率响应。

## 光路与端口关系

四次通过有源电极的方向全部为从左向右：

1. 第一程以TE0通过上方有源波导；
2. 第一回路从右侧返回左侧，经模式复用后以TE1进入第二程；
3. 第二回路从右侧返回左侧，并切换到下方有源波导，以TE0进入第三程；
4. 第三回路再次返回左侧，经模式复用后以TE1进入第四程；
5. 第四程从右侧输出。

这里的模式复用器本体采用现有750 µm EME名义几何。复用器主体的转换结果已经单独验证；它与1.33 µm有源波导、0.7 µm无源回路之间新增的渐变连接和辅助端尾端仍需做完整EME或FDTD级联验证。

## PDK层与结构处理

- `20/0`：LN1波导核心；
- `20/1`：LN1波导包络；
- `10/2`：波导下方的SiN挖除窗口；
- `42/0`：顶层金属；
- `100/0`、`101/0`：黑盒边界、端口名和检查标记，仅出现在工作版GDS中。

生成器在全部LN光路下同步绘制`TRENCH_SIN`，对应当前“SiN移除后以SiO2填充”的结构假设。它不替代代工方正式版图规则；最终流片前仍要使用完整PDK做官方DRC。

## 生成方法

项目虚拟环境安装依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-layout.txt
.\.venv\Scripts\klink.exe plugin install
```

KLayout必须以可编辑模式启动，否则KLink只能读取而不能插入图形：

```powershell
Start-Process "C:\Program Files\KLayout\klayout_app.exe" -ArgumentList "-e"
```

启动后先检查KLink连接：

```powershell
.\.venv\Scripts\klink.exe doctor
```

保存当前KLayout中需要保留的工作，再运行名义版图生成器：

```powershell
.\.venv\Scripts\python.exe models\layout\generate_four_pass_gds.py --replace-active-layout
```

默认参数为10 GHz、15 mm有源电极和3T、3.5T、3T三段回路。可在保持第一、三段为整数周期、第二段为半整数周期的条件下显式修改：

```powershell
.\.venv\Scripts\python.exe models\layout\generate_four_pass_gds.py `
  --loop-periods 3,3.5,3 `
  --replace-active-layout
```

`--replace-active-layout`会替换当前KLayout页面中的版图，因此仅在已经保存当前页面、确定要重新生成时使用。脚本不会删除磁盘上的历史结果。

## 本轮有限重算结果

为区分“回路时延改变”和“电极长度改变”，系统模型对两组方案都固定使用15 mm有源电极：

| 项目 | 2T、2.5T、2T相位对照 | 3T、3.5T、3T版图候选 |
| --- | ---: | ---: |
| 10 GHz四程相干增强 | 3.9993 | 3.9993 |
| 10 GHz有效半波电压 | 1.6715 V | 1.6715 V |
| 高于最强梳齿−20 dB的理想谱线 | 32根 | 32根 |
| 模型3 dB射频区间 | 9.487–10.510 GHz | 9.646–10.351 GHz |

这说明增加整数周期不会破坏10 GHz中心点的理想相位叠加，也不会在中心点自动增加梳齿数；主要变化是离开10 GHz后相位误差积累更快，因此工作区间变窄。这里仍是未计入复用器反射、弯曲损耗和各程幅度不均衡的系统级工程模型。

新版系统结果保存在`results/system/版图候选_3T_3.5T_3T/`，同电极长度的历史相位对照保存在`results/system/历史相位对照_2T_2.5T_2T_15mm/`。两者都是本机结果，不提交Git。

## 尚未签核

0. 已发现的斜交应改成受控交叉器；PDK黑盒缺少本地真实掩膜和复S矩阵，尚不能给出本PDK下的交叉损耗、串扰、反射或时延。快速EME相位扫频中固定LN折射率也未包含材料色散，不能作为最终群时延签核。

1. 四个模式复用器、全部渐变段和辅助端尾端的完整光学级联；
2. 依据复数散射参数相位提取的各段群时延，而不是当前有效群折射率估算；
3. 实际欧拉弯曲的光学损耗和模式串扰；当前GDS弯曲为圆弧离散近似；
4. 射频输入焊盘、50 Ω终端、探针过渡和完整金属DRC；
5. 版图最终连通性、官方PDK DRC和流片标记；
6. 工艺容差。容差按项目约定放在功能级联验证之后处理。

因此，这一版可以作为名义联合仿真的实际版图起点，但不能称为流片签核版。
