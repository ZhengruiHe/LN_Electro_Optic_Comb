# KLink连接诊断

检查日期：2026-09-09。本轮只诊断，不重装、不修改插件或Windows安全配置。

## 实际发现

- 检查时没有常驻KLayout进程，也未发现127.0.0.1的8765–8799端口监听。因此本次连接拒绝的直接原因是没有运行中的KLink服务端，不是已发现权限/防火墙拦截。
- 本地项目Python中的klayout-klink客户端及已安装KLayout插件均为0.5.8，官方本地`plugin status`返回一致。
- 已安装插件的`pymacros/klink.lym`设置`autorun=true`，启动脚本调用`klink_server.start()`。目前没有证据表明需要重装插件。
- KLink由KLayout进程托管，不是独立常驻的Windows服务。关闭对应KLayout窗口，进程和监听端口便会消失；一次性KLayout批处理退出也不能提供持续可连接的GUI会话。
- 服务端默认从8765开始选端口，占用时会寻找其他端口，最大8799。项目部分旧脚本直接调用`KLinkClient()`或默认`--port 8765`，因此多开实例、旧实例退出后，可能连错端口或找不到仍在运行的其他实例。这是代码中存在的连接可靠性问题，但不能据此认定每一次历史失败都由同一个原因造成。

## 正常使用方式

1. 需要交互查看时，正常打开KLayout GUI，保留该窗口；不把一次性`-b`批处理当常驻服务。
2. 查看工具栏`K8765`、`K8766`等标记，其数字是该实例实际监听的端口。
3. 先做端口发现与握手，再按目标文件和cell选择实例；不要每次只假定8765，更不要因连接拒绝就先重装或改防火墙。
4. 多实例时，端口与版图文件均需对应。窗口关闭或服务重启后重新发现，不依赖前一天的端口。

本地只读诊断命令：

```powershell
.\.venv\Scripts\python.exe -m klink.cli plugin status
.\.venv\Scripts\python.exe -m klink.doctor --scan --json
```

`doctor`中的可选Python扩展缺失与GUI插件无监听是不同问题，不应仅凭可选依赖提示就重装整个环境。若GUI确实运行而所有端口均无监听，再检查宏加载报错及是否用了禁用插件/不同配置目录的启动方式。

本轮未修改启动配置、未创建新后台服务，也没有停止或重启用户进程。
