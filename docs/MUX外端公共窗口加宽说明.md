# MUX外端公共窗口加宽

## 最新工作稿

`results/layout/_历史归档/迭代版本_20260912/MUX外端公共窗口加宽_工作稿_v11_01/四程10GHz_15mm_MUX外端公共窗口加宽_待验证工作稿.gds`

本版按用户确认，在v10基础上只扩大四个MUX外端最后200 µm的公共绘制窗口。两条0.7 µm LN1脊、MUX光学本体、有源波导、M1电极、圆弯、长回路和所有实例位置均不改变。

## 加宽方式

MUX局部外端的两条波导中心分别为主路`y=-1.80 µm`、辅助路`y=1.45 µm`，中心间隔3.25 µm。

- `20/1`：v10主体边界为`-6.00...2.10 µm`。在局部`x=750...950 µm`增加上侧矩形覆盖至`y=5.05 µm`，最终外端公共区域为`-6.00...5.05 µm`，完整覆盖两条各7.2 µm的外部包络。
- `10/2`：v10主体边界为`-10.55...6.65 µm`。同一区段增加上侧矩形覆盖至`y=10.05 µm`，完整覆盖两条各17.2 µm的SiN挖除窗口。

这里采用矩形局部加宽，而不是移动包络中心或弯曲光学脊。加宽区在四个镜像MUX中自动随实例方向变换。

## 核查结果

- 四个MUX、两个工艺窗口的主路/辅助路接口全部完整宽度覆盖；
- 加宽只发生在每个MUX的外端200 µm，原窗口区域没有删除；
- 整片`20/0`和M1完全未改变，实例位置未改变；
- `20/1`与`10/2`保持单连通；
- LN核心间距、刻蚀区线宽、SiN窗口线宽/间距及M1线宽/间距无新增标记；
- 仍有40条LN核心线宽和40条LN1刻蚀区间距标记，来自MUX本体辅助脊的法向宽度/1 nm格点问题，并非外端加宽新增。

这是名义几何连接工作稿。局部扩大`20/1`和`10/2`会改变实际刻蚀边界，必须在最终截面下重新核对光学模式、边界散射和射频介电加载。21层、圆弯、10 GHz时延、RF焊盘和终端仍暂缓，不能据此声称流片签核通过。

## KLink状态

KLink不是Windows后台服务，而是由某一个KLayout进程托管。托管窗口关闭后，监听端口随之消失；多个KLayout实例还会依次使用8765、8766等端口。2026-09-07本轮重新启动了正常KLayout实例并确认`127.0.0.1:8765`监听，新v11已在该实例打开。

若再次出现连接拒绝，应先查看工具栏是否有`K8765`或其他端口标记，再按对应端口连接；若没有标记，正常重启一个KLayout窗口以触发`klink.lym`自动运行。无需重新安装插件。

## 复现

生成过程使用KLayout批处理，不依赖常驻KLink服务：

```powershell
.\.venv\Scripts\python.exe -X utf8 models/layout/widen_mux_external_windows.py `
  --output-dir results/layout/自己的MUX外端加宽新目录
```

脚本读取v10后另存，禁止覆盖已有目录，并保存检查JSON。生成后可用KLayout/KLink打开检查。
