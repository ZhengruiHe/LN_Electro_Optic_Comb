# MUX有源端包络对齐

> 本文记录的v7方案已因包络斜向漂移被否决。最新重新规划方案见`docs/MUX连接重新规划说明.md`；v7仅保留为历史反例。

## 最新工作稿

`results/layout/MUX包络四处对齐_工作稿_v7_01/四程10GHz_15mm_MUX包络四处对齐_待验证工作稿.gds`

v6中每个MUX的共同包络以局部横向中心`y=0`布置，而接入电极区的主脊中心位于`y=-1.95 µm`。有源区的包络又以主脊为中心，因此二者端面中心相差1.95 µm，形成截图中的矩形台阶。该台阶不是模式复用功能，也不是刻意的光学设计。

v7在共享MUX单元的有源侧`x=-200...0 µm`内同步调整：

- `20/1`第一遍LN刻蚀绘制包络，宽度保持7.2 µm；
- `10/2`下方SiN挖除窗口，宽度保持17.2 µm。

包络中心从有源端`y=-1.95 µm`平滑移动到MUX本体端`y=0`，采用三次平滑函数，两端斜率为零。共享单元有四个实例，因此左上、左下、右上、右下四处同时修正。1.33 µm LN1主脊、电极、MUX本体的两条光学脊、v6尾端、黑盒、圆弯和21层均未改变。

## 核查结果

- 四处`20/1`和`10/2`接头均完整覆盖端面宽度，没有断口；
- 两层只在每个MUX的200 µm有源侧过渡区域变化；
- 其他子单元、其他工艺层以及v6源文件均保持不变；
- `20/1`刻蚀区最小线宽检查为0项，`10/2`最小线宽/间距均为0项；
- 整片仍有40条LN核心线宽和40条LN1刻蚀区间距标记，位置均在MUX本体辅助脊的局部`x=0...87.5 µm`附近，并非本次包络过渡新增。

当前结论只是名义几何对齐。包络变化会改变实际刻蚀边界，因此仍需在包含有源端接续的完整MUX模型中验证目标模式传输、反射、串扰及群时延。本轮未做容差、21层、欧拉弯、射频焊盘或终端，不代表流片签核通过。

## 复现

KLayout加载KLink后运行：

```powershell
.\.venv\Scripts\python.exe -X utf8 models/layout/align_mux_envelopes_layout.py `
  --output-dir results/layout/自己的包络对齐新目录
```

脚本读取v6并另存，禁止覆盖已有目录；输出检查JSON和左右两侧截图，并在KLayout新标签中打开v7。
